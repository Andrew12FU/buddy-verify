> capture 的 profile 限制和旧拒绝范围为历史记录；当前统一规则见 [GENERIC_CAPTURE.md](GENERIC_CAPTURE.md)。

自动运行快照已按保留策略清理；本文保留历史发现，当前通过版本见 [MiniMLIR/current](../../MiniMLIR/current)。

2026-11-17。扩展现有 `capture` 规则，不新增命令行规则名，不修改原 pass 或其 mini。改写后的 C++ 仍需要原生检查和 Frama-Clang 转换；接口抽取先驱模块保持现有实现。

## 适用范围与改写形式

当前支持含类对象引用捕获的非泛型嵌套组：两层、三层及按同样算法递归处理的更深层次；空捕获的外层；同一原对象逐层捕获；内层捕获外层局部类对象或类对象参数；兄弟闭包；具名自动变量初始化；立即调用；仅复制继承指针时，在块直属 return 前放置指针副本。已转换的独立样例覆盖两层、三层与外层局部对象，未声称所有深度和所有 C++ 上下文均已转换验证。

例如：

```cpp
Box box;
consume([&]() {
  consume([&]() { box.add(1); });
});
```

生成以下结构：

```cpp
Box box;
auto *boxPtr = &box;
consume([boxPtr]() {
  auto *boxPtr1 = boxPtr;
  consume([boxPtr1]() { (*boxPtr1).add(1); });
});
```

每层捕获的是指针值，不是指针局部变量的引用。外层闭包返回或销毁后，内层仍持有地址副本；原 `Box` 的生命周期责任不变。若类对象是在外层函数体内定义，第一次取地址也在该函数体内、对象定义之后进行，不会提到外层闭包之前。

## 额外汇报：旧边界与新发现的不适配

1. **旧 capture 明确拒绝嵌套闭包。** `BodyFacts.NestedLambda` 原先触发整份拒绝。本轮由独立嵌套规划器接管这类组；非嵌套输入继续走原单层路径，普通单层声明初始化的 profile 限制未放宽。
2. **父子分别改写会导致补丁范围重叠。** 最外层 lambda 现在统一负责整棵捕获树。子捕获列表、引用、体内指针声明先合成为局部编辑，再提交一个根替换；子 lambda 的后续 AST 回调不重复提交。普通全局重叠拒绝规则保持原样。
3. **直接逐层捕获同一个指针名，原生执行通过而 Frama 转换失败。** 最初尝试 `[resultPtr] { ... [resultPtr] { ... } ... }`，C++ 编译/执行均 0，但转换链报 `Cannot resolve variable resultPtr`。失败完整保留：原生检查（历史自动产物已清理）、失败输入（历史自动产物已清理）、转换失败日志（历史自动产物已清理）。本轮采用 `auto *resultPtr1 = resultPtr;`，让内层捕获函数体中有明确声明的局部指针副本，随后同一类样例转换成功。这是当前转换工具链的实测名称解析限制。

第三项的局部副本只复制地址，不复制类对象，不重新执行对象访问，不采用 `&(*ptr)`，不调用类的取地址重载，也不引入新库 API。

## 仍保留的边界

需要改写的捕获组中，按值复制类对象、混合标量/指针捕获、this、初始化捕获、引用类型变量、泛型、局部类方法作用域、宏、未求值使用及检测到的重载取地址等继续拒绝。按值复制边界不能用外部原对象指针越过，否则内层原本访问的副本会被误改为原对象。

新增声明只放在同块直接表达式、单个自动局部变量声明，或仅继承指针副本的直属 return 前。条件表达式、逻辑短路、赋值、多变量/静态初始化、需要新取地址的 return 等不在本轮范围。完全没有目标类引用捕获的组保持原样，不强行转换其标量捕获。

不同业务规则若修改同一根 lambda 的内部范围，全局计划仍可能因重叠而拒绝；本轮只组合捕获树内部的编辑，不承诺任意规则组合。没有增加逃逸分析、对象所有权或生命周期延长，不证明原本悬空的引用有效。
