# 实际尝试结果与抽取粒度因素

日期：2026-11-16。以下为先驱实验的实测结论，尚未决定完整抽取体系。模块现位于统一前端的 `experiment/interface_pilot/`，C++ 实现位于 `src/interface/`；迁移不改变历史结论。

最终证据：[本轮摘要](../results/20261116-211749-088826/summary.json)、[39条实际命令及退出码](../results/20261116-211749-088826/commands.json)、[抽取来源和成员清单](../results/20261116-211749-088826/extraction_manifest.json)。所有成功/失败日志均在同轮 `logs/` 中。

本轮39条命令包含工具版本检查、AST观察、原生解析、链接、执行、类型性质、constexpr、负例和两次Frama转换。37条有成功/失败预期并全部符合，2条Frama命令作为观测记录，均退出0并产生非空C。不是“39个语义测试通过”。指定原件的哈希在运行结束保持不变。

第一轮[失败摘要](../results/20261116-211457-375388/summary.json)保留：真实ArrayRef用例不链接LLVM库时出现`llvm::EnableABIBreakingChecks`未解析。第二轮保留这一失败，并另行链接Buddy配套`libLLVMSupport.a`后成功；没有改写第一次的现场。

## 1. 只取公开、直接调用到的成员，不构成足够的头文件

真实 `LogicalResult` 有6个显式成员。从 `llvm::failure(bool)` 和 `llvm::failed(LogicalResult)` 出发，只有直接调用的两个公开方法时，生成头在原生Clang下失败：静态failure方法需要私有bool构造，failed方法需要私有IsSuccess字段。

从短方法体自动递归追踪调用、构造和字段引用后，得到4个所需成员：failure、failed、私有构造及字段。两个未用到的方法success/succeeded没有纳入。

| 生成方式 | 原生解析 | 链接/运行 | Frama转换 |
|---|---|---|---|
| 仅直接公开方法，保留体 | 失败 | 未继续 | 未继续 |
| 自动短实现依赖闭包 | 通过 | 链接通过，真假两条结果路径运行通过 | 退出0，生成4748字节C |
| 函数只留声明、删除字段 | 通过 | 链接失败 | 退出0，生成4006字节C |

证据：[闭包自动头](../results/20261116-211749-088826/extracted/logical_closure_bodies.h)、[直接成员失败日志](../results/20261116-211749-088826/logs/logical_surface_syntax.log)、[闭包运行](../results/20261116-211749-088826/logs/logical_closure_execute.log)、[声明模型转换](../results/20261116-211749-088826/logs/frama_logical_declarations.log)。

**对粒度的影响**：需要明确区分“声明依赖”“保留实现所需依赖”“证明性质所需状态”。选中某个方法后，是否保留体，会决定是否需要继续纳入私有字段和辅助构造。

**对规约的影响**：只有声明的failure/failed还没有规定二者的关系。转换成功不能代替有关成功/失败编码的契约。保留本次真实短体和状态是一个可尝试的方案；用抽象逻辑状态加契约也是一个方案，本轮没有推导这些契约。

## 2. 签名可解析，不代表类型性质保持

同一个 `LogicalResult` 在真实头和自动闭包模型下，`!std::is_empty_v<LogicalResult>`都成立。删除字段的声明模型仍能解析调用，但这一静态断言失败。

完整Matmul观察还看到：现有人工mini中的LogicalResult由非聚合变成聚合；RewritePatternSet的析构由非平凡变成平凡。记录于[真实类型清单](../results/20261116-211749-088826/observations/matmul_real.json)和[mini类型清单](../results/20261116-211749-088826/observations/matmul_existing_mini.json)。这些是可观察抽象差异，不表示本轮已经证明pass运行有误。

证据：[删除字段后的类型性质失败](../results/20261116-211749-088826/logs/logical_declarations_trait.log)。

**对粒度的影响**：不能把空类视为任意真实类的无害替代。字段、特殊成员、基类和访问性可能影响聚合初始化、traits、临时对象清理与重载。应列出哪些性质必须保持，哪些差异允许并需要记录；不能为凑出性质任意新增虚析构或占位字段。

**对规约的影响**：最终IR模型还需要句柄身份、共享状态和失效关系；“保留几个字段”本身并未解决这些语义问题。该部分尚未实证。

## 3. 删除模板约束，既能改绑重载，也能错误接受输入

自动切片保留ArrayRef容器构造的真实SFINAE约束。使用一个可转换为`const int&`、却没有data/size的ScalarLike类型：

| 接口 | 解析 | 实际选中的构造 |
|---|---|---|
| 真实ArrayRef | 通过 | `ArrayRef(const int&)` |
| 保留约束的自动声明 | 通过 | `ArrayRef(const int&)` |
| 人为删除容器构造约束 | 通过 | `ArrayRef(const ScalarLike&)` |

再用完全无关的Unrelated类型：真实头与保留约束模型均拒绝；无约束声明模型接受。

证据：[三个构造绑定](../results/20261116-211749-088826/array_bindings.json)、[真实负例](../results/20261116-211749-088826/logs/array_real_negative.log)、[无约束模型错误接受负例](../results/20261116-211749-088826/logs/array_unconstrained_negative.log)。无约束模型是有意消融，不作为可复用接口。

**对粒度的影响**：调用点已选中的一个签名，不足以定义未来调用的候选集合。模板约束、转换构造、其他竞争重载和负例同样重要。保留原模板还是对已审计实例归一化，需要显式策略与范围。

**对规约的影响**：契约应关联实际声明身份与特定重载，不能仅按函数名附加。误选构造意味着适用的前置条件和行为可能也变了。

## 4. constexpr让某些函数体成为编译期依赖

`constexpr ArrayRef<int> ref(data, 2);`在真实头与自动短体模型下通过。保留同样constexpr构造声明、但删除定义后，普通运行期调用仍能做语法检查，常量初始化却失败：未定义构造不能用于常量表达式。

证据：[constexpr失败日志](../results/20261116-211749-088826/logs/array_declarations_constexpr.log)、[对应自动声明头](../results/20261116-211749-088826/extracted/array_declarations.h)。

**对粒度的影响**：不能全局采用“外部函数一律删体”。constexpr使用、模板推导、约束计算或依赖返回类型等场景应分类。本轮只验证constexpr对象初始化，其余几类仍需后续用例。

**对规约的影响**：后续行为契约不能替代编译器当前所需的常量求值定义；模型首先要保持所选C++表达方式可编译。

## 5. 私有字段、类型别名和宏共同决定源码切片是否闭合

真实ArrayRef记录到49个显式成员，本轮人工限定的成员策略自动切出10个，包括Data/Length、size_type及部分构造和访问方法。仅从源码复制这些片段仍失败，因为参数上保留了未定义的`LLVM_LIFETIME_BOUND`。

从真实预处理回调保存该对象宏的替换tokens后，保留字段/原约束/短体的模型解析并运行通过：长度为3，索引取到5，data指向原数组。再删除Data/Length而保留体，立即解析失败。

证据：[闭合自动头](../results/20261116-211749-088826/extracted/array_closed.h)、[未带宏的失败](../results/20261116-211749-088826/logs/array_raw_syntax.log)、[缺少字段的失败](../results/20261116-211749-088826/logs/array_no_fields_syntax.log)、[数组模型运行](../results/20261116-211749-088826/logs/array_closed_execute.log)。

**对粒度的影响**：AST中的语义声明与能直接再编译的源码不是同一种产物。必须处理宏、别名、访问区段、声明顺序和类型依赖。当前只自动快照这一对象宏；函数式宏、条件编译及任意展开尚未解决。ArrayRef外壳的类级GSL/nodiscard等属性也没有完整复制，不能声称完全保真。

**对规约的影响**：寿命属性本身不建立证明。ArrayRef是非持有视图，后续仍要描述底层区间有效性、索引范围、别名及存活时间；本轮只运行了活数组上的有效访问，没有证明悬垂或越界安全。

## 6. 完整pass的隐式节点、基类和宏不能只按函数名处理

对原始MatmulScalar，只更换include并保持行数后，真实头与原有人工mini均解析成功，各有83个调用/构造节点。按位置、类别、声明所属名称、canonical签名、结果类型和默认参数等比较，65项完全相同，两侧各18项未逐项相同。

这个比例不是准确率、覆盖率或等价性分数。差异包括：

- getRank在真实模型中来自ShapedTypeTrait，现有mini直接声明在RankedTensorType；签名相同但声明身份改变。
- getType/getLoc/getContext以及Operation*转换来自真实trait/OpState，mini有意压平到操作类。
- 某些Attribute/Type转换路径中，一侧是转换成员调用，另一侧是包装构造。
- TypeID宏在真实AST中生成SelfOwningTypeID构造及转换，mini宏仅保留声明。
- FrozenRewritePatternSet涉及的string类型打印也有差异，需要进一步核对ABI/别名归一化；本轮不把它直接判成错误ABI。

原始Matmul的83个节点中，13个节点使用默认实参，30个节点记录到模板实例来源；还观察到5条override边。LowerIME观察到22个调用/构造节点、19项主文件所用类型、5条override边及TypeID宏。类型条目只是当前观察清单，不是全部类型依赖闭包。

证据：[完整pass对照摘要及未匹配项](../results/20261116-211749-088826/pass_comparison.json)、[LowerIME真实观察](../results/20261116-211749-088826/observations/ime_real.json)。

**对粒度的影响**：需要从调用表达式、隐式构造/转换、默认实参、模板实例、override关系和宏生成代码共同选种子。继承压平必须记录真实声明到模型声明的映射，不能仅将同名成员合并。

**对规约的影响**：API契约、虚覆盖契约和pass自身契约应分别关联。相同方法名并不意味着相同状态或相同派发行为。

## 7. 解析、链接、运行和转换是不同边界

ArrayRef真实头会经配置头引入ABI检查符号。第一轮只编译最小使用程序但不链接LLVM库，链接失败；配套Buddy的Support库可消除该符号失败并运行通过。自动切片没引入这一头文件级检查，运行不需要该库。

证据：[不链接库的失败](../results/20261116-211749-088826/logs/array_real_link.log)、[配套库链接成功](../results/20261116-211749-088826/logs/array_real_link_support.log)。

**对粒度的影响**：真实声明之外，还存在头文件级变量、构建配置和库边界。去掉它们可能是有意抽象，但需记录。不能随意用另一LLVM版本的库或伪造符号“修复”对照。

**对规约的影响**：本实验的运行只是小程序行为对照。没有执行完整MLIR pass，也没有证明外部API实现满足契约。

## 可据此讨论的策略，而非已经确定的体系

| 决策 | 本轮证据支持的讨论起点 | 仍需决定 |
|---|---|---|
| 选择抽取根 | 记录真实绑定、隐式节点和来源，而非文本函数名 | 面向单个pattern、整个pass还是入口可达调用链 |
| 保留实现还是契约 | LogicalResult短体很小且可闭合；纯声明仍可转换 | 允许保留哪些短体，哪些API以受审阅契约承担证明假设 |
| 类型表示 | 不随意把全部类型变成空类 | 证明依赖哪些类型性质，哪些对象需要共享IR状态/身份 |
| 模板策略 | 保留约束并做正/负例，不只检查成功调用 | 原模板保留或受限实例化的边界 |
| 继承策略 | 保留真实成员身份；压平时登记映射 | 哪些基类/traits能压平，override及契约如何继承 |
| 宏与版本 | 记录生成头位置、宏配置和编译参数 | 保留调用、复制定义、消除展开或独立适配的选择 |
| 验收目标 | 分开记录解析、绑定、性质、链接/运行和转换 | 后续哪些成为每类接口的必需检查 |

尚未通过本轮实验证实的重点：IR创建/替换/删除的抽象状态与修改范围、回调执行/逃逸、别名与句柄失效、异常及回滚、任意模板依赖闭包、完整生成头的Frama兼容性、ACSL承载/映射及WP证明。它们应有下一轮独立试验，不能由本轮小模型的成功推出。

建议先讨论“第一条要验证的pass性质”和“可接受的外部API假设”。这两个选择决定语义模型的下限；静态抽取的默认保真要求则可以先保守设置。当前先驱代码不替这些问题作最终决定。
